# Architecture Decision Records (ADR)

## Purpose

Document important architectural and design decisions made during development. This helps understand WHY decisions were made, not just WHAT was done.

---

## Format

Each decision follows this structure:
1. **Context** - What situation led to this decision?
2. **Options Considered** - What alternatives were evaluated?
3. **Decision** - What was chosen?
4. **Consequences** - Impact (positive and negative)
5. **Date** - When was this decided?

---

## When to Create an ADR

Create an ADR when you:
- Choose between different technologies
- Change the architecture significantly
- Make design decisions that affect the whole project
- Choose patterns or approaches that will impact future development
- Decide on third-party integrations

**Don't create ADRs for:**
- Minor implementation details
- Simple bug fixes
- Obvious choices
